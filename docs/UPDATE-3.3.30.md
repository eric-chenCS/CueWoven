# CueWoven v3.3.30

**No more duplicates.** Pages get one identity however they're reached: www/m./mobile hosts, http and https, trailing slashes, AMP, common tracking tags (utm, fbclid, gclid, igsh, smid, si, share and others) and parameter order no longer create a second copy. Instagram /reel/ and /p/ links, twitter.com and x.com, and old.reddit.com and reddit.com each count as one. Parameters that change the content, such as GitHub's ref or a video's t, stay distinct, and saved items keep and open their original address. Feed videos whose player uses a temporary blob: address are identified by stable clues (preview image, caption, title, length) instead of an address that changed on every page load. Backups with address-hashed IDs still restore, while forged IDs are still rejected.

The daily cleanup, which also runs shortly after the extension starts, merges pages and feed videos already saved more than once, keeping the most recently watched copy. As a fallback, search shows only the better-scoring copy when two results share a title, site and matching text, before paging and before the near-tie check, so a copy can't show as a second result or a false **Almost as good**.

**Lighter Add videos.** Background caption fetching now defaults to 3 videos at a time instead of 6 (1, 3, 6 or 10 remain available). **Fetch missing transcripts (N)** appears only when some saved videos are title-only or have AI speech for just the played parts.

Validation: all 290 Node tests pass, including identity rules, backup compatibility, duplicate cleanup and the search fallback, which fail without the change. In Chromium, a duplicated video searched through the real model shows once with no near-tie, and the Fetch missing transcripts button hides and shows with its count. The single-video, refine, Enter-search, preferences, Add videos (background transcripts), web storage, web migration and backup checks pass, and the 30,000-passage search benchmark stays at about 127 ms. web-pages fails identically on v3.3.29 (it expects an older link format), and web-media needs a local speech fixture, so the blob-address change has unit-level but not browser-level coverage. No permissions, dependencies or storage format changed.
