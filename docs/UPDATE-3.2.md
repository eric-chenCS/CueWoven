# Recall 3.2.0 — large-history paging, storage and capture status

This update applies the measured performance and data-control improvements from the supplied review. It keeps combined text/scene retrieval and existing opt-in site permissions. There is no model/dependency or database-schema change.

## Changes shipped

- **Cached ranked windows.** A query, time filter, source filter and per-item limit share a short-lived result cache. Three windows of 256 hits are kept for up to 30 seconds. Arrows within a window reuse text embeddings, database ranking and scene-query inference; only the displayed scene previews are read. Going farther computes another window, so the cache does not restrict the library to the first 200 matches. Concurrent identical requests share work. Library changes invalidate pending and completed snapshots; a canceled/deleted snapshot is never published later. Scene-search errors are retried rather than retained in cache.
- **Larger bounded reads.** Web-item scans use batches of 500 instead of 32, cutting the number of requests for a 50,000-item library from about 1,563 to 101. The extra transient memory is bounded by existing content budgets and the batch size. Full web passage vectors are not duplicated into a permanent second index. A metadata-load race during Clear/reset is also fixed.
- **Storage protection and visibility.** The manifest declares `unlimitedStorage`. This exempts extension storage from ordinary quota eviction in Chromium, while disk capacity, explicit deletion/uninstall and Recall's own scene/text budgets still apply. Library & settings shows approximate origin usage, including downloaded model caches, and whether the permission is enabled. This does not grant any additional website access. See [Chrome's extension storage documentation](https://developer.chrome.com/docs/extensions/develop/concepts/storage-and-cookies).
- **Imported-history retention.** Keep imported history offers Forever (the default), 1 year and 90 days. The optional limit uses the original visit/watch date, even if background captions were fetched later. Choosing a limit cleans existing old imports immediately and the daily cleanup enforces it afterward. Later imports are included in daily cleanup. Records lacking a valid original date stay protected. Live captures continue using their existing activity-based retention. Export a backup before choosing a shorter retention period if you want a separate copy.
- **Capture diagnostics.** Allowed web pages report saved, duplicate, paused, excluded, private-form, hidden and too-short outcomes; YouTube reports saved, duplicate, paused and unavailable-caption outcomes. The last 100 events stay in `chrome.storage.session`, with repeated reasons throttled. Only time, domain, source kind, outcome and a fixed reason code are recorded: no full URLs, titles, query text, page content or incognito events. Library & settings has Refresh and Clear log. The popup shows current-page status, including missing permission/refresh/model loading, Save this page now, and Forget and block site. The latter removes that site's existing entries and blocks future capture. Unsupported or ungranted pages cannot be saved through these controls. Incognito YouTube indexing is also explicitly refused.
- **Performance regression checks.** The 30,000-full-passage rank benchmark now fails above a default 400 ms budget. The large-library browser benchmark records median/p95 and fails above a calibrated 1,000 ms new-query p95 or 50 ms arrow p95. These are separate commands from the ordinary Node suite and use environment overrides for deliberate hardware calibration; `RECALL_PERF_CHECK=0` allows diagnostic-only comparison. No slow run is silently reclassified as passing.

## Measurements and checks

All **205 Node tests** pass, including pending cache invalidation, coalescing, deep paging, cache expiry, filter-key separation, metadata-reset races, original-date retention, incognito denial, log redaction, throttling and the 100-event cap. Deliberately removing the query-cache revision increment makes the stale-snapshot regression fail; the correct code was restored.

An isolated Chromium fixture contains **50,000 synthetic titles plus 600 full 2,000-word pages** (9,000 content passages; approximately 51.9 MB of accounted full web content). It uses actual IndexedDB and MiniLM query embeddings, with synthetic zero stored vectors so that lexical retrieval and database overhead remain measurable. Eight different broad queries and three arrow requests per query were measured after runtime/model warmup:

| Build | New-query median | New-query p95 | Arrow p95 |
| --- | ---: | ---: | ---: |
| v3.1 package | 717 ms | 1,035 ms | 752 ms |
| verified v3.2 package | 531 ms | 796 ms | 8 ms |

These are test-machine observations, not a latency promise for every device, query or library. The proposed 300 ms target for every new large-library query is **not achieved**. Cached arrows are much faster; new queries still scan and score the library. New scene queries still run CLIP when saved scene evidence exists. The full-passage in-memory rank benchmark remained about 142 ms, excluding model load, query embedding and IndexedDB.

Browser regressions cover article capture, source filters, form exclusions, responsive layout, native caption/CLIP/OCR/Whisper evidence, timestamp links, backups, query-cache invalidation after mutations, and delete/restore capture holds. A separate diagnostics test verifies actual storage permission/estimate, popup save/forget, session log contents and the retention dropdown removing an old import while retaining a recent one. Native permission dialogs are not automated. The current release has not been installed/reloaded or tested in the user's regular profile by automation; earlier live/public and user-confirmed results remain documented under their original versions.

## Review decisions on the other suggestions

| Suggestion | Decision |
| --- | --- |
| Packed in-memory web index | A packed title-index experiment added about 19 MB of vector payload and did not reliably improve the large-library result. It was reverted. Keeping all full-page vectors/text in another memory index needs a demonstrated benefit and a device-memory budget. |
| Skip scenes for queries guessed to be nonvisual; stage/debounce scene results separately | Deferred. A guess could hide the scene the user remembers; two-stage results also change ranking/Enter/arrow behavior. Combined evidence is preserved, and the query cache already removes repeated CLIP work during paging. |
| Battery/15-second inference budgets | Deferred pending device profiling. An arbitrary budget silently drops OCR/scenes and is not an energy measurement. Existing scene, OCR, speech and capture off switches remain available. |
| 50-query mixed-source accuracy evaluation and local thumbs feedback | A curated mixed-source ground-truth corpus would be useful; it is not replaced with a manufactured accuracy score. Existing retrieval fixtures and real-model browser checks remain. The evaluation/feedback interface is deferred; no votes or extra query logs are collected. |
| Omnibox, natural-language date ranges, recent-range deletion and timeline | Deferred as separate product changes. Date interpretation can accidentally filter memories about a date, and recent deletion needs clear visit-date versus capture-date semantics across every evidence store. No partial version is introduced. |
| Extra text-fragment fallback marker | Deferred because SPA/hash navigation and stale passages can cause wrong scrolling/highlights. Existing browser text fragments remain. |
| Search-to-page provenance from a two-minute visit gap | Deferred: temporal proximity does not establish which search led to a page. The extension does not display a guessed causal history as fact. |
| Normal-profile demo checklist | Still a manual verification step after reload. Tests use synthetic history, controlled players or public isolated pages; they do not read personal browsing history/accounts or claim production Instagram/TikTok support. The statement that no live YouTube test ever existed is too broad: historical public-video speech and user-confirmed Edge results are already recorded. |
| Local summarizing language model | Not added. The current local models already have a substantial memory/CPU cost. |

Reload Recall in the same installed folder and refresh website/YouTube tabs. No vendor rebuild or history re-import is required. New host access stays opt-in. Existing dependency audit findings are unchanged: three high and one moderate findings in native Node dependency paths previously documented as excluded from the browser runtime; the locked graph is not audit-clean.
