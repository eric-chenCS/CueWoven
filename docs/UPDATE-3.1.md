# Recall 3.1.0 — public-page capture and indexing fixes

The eight reported concerns were valid or materially useful to address. These changes preserve opt-in website access, local processing and the existing models.

1. **URL filtering:** known sensitive domains and hostname checks remain. Private route checks apply to the first decoded path segment (including hash-based routes), rather than arbitrary words in a deep article/file path. Public Email/Bank/Health Wikipedia articles, Python email documentation, GitHub `global_settings.py`, NYTimes `/section/health` and Stack Overflow OAuth-question paths pass regressions. Public root-level topic names such as `/health` also pass; actual account/login/settings/inbox routes remain blocked. Credential, token, local-network and incognito guards remain.
2. **Search:** passages store normalized text once. A query's normalized phrase, quoted phrases and metadata evidence are prepared/reused once; exact word checks no longer rebuild Unicode-normalized token sets for every passage. Weak semantic candidates with no query-word substring skip detailed evidence checks. Exact/quoted low-vector matches, Unicode/accent handling, word boundaries and score ordering remain tested. YouTube captions and OCR use the same optimization.
3. **Imports:** each web-history request embeds its pending titles together (the model wrapper still splits into bounded inference batches of 16), then sends one library-change notification for the request. Duplicate-only batches do no embedding work. Settings defer full-library list refreshes during the import and refresh afterward; progress remains available. Cancellation still prevents pending titles from appearing after a destructive mutation.
4. **Clicked results:** Takeout Google `/url` entries unwrap `q` or `url` to the destination, validate that destination through the same policy, strip supported localized Visited prefixes, remove tracking parameters and deduplicate with Chrome visits. Unsafe/sensitive targets are skipped. This applies when importing; previously saved redirect records are not silently rewritten. Re-import to bring in formerly excluded public pages or corrected destination records.
5. **Forms/editors:** hidden password/login popups no longer block a public page. A rendered password field still blocks capture. A small comment box is excluded from extracted text without rejecting the article; an editor occupying at least half the visible viewport blocks capture. An explicit `data-recall-private` marker still blocks the page. These heuristics cannot identify every private page.
6. **Recapture:** automatic page text capture waits at least 60 seconds after a successful save; explicit Index now can run sooner. Existing passage vectors are reused by exact text, with fresh offsets/anchors and normalization. Only changed/new text is embedded, including title changes. This is exact passage reuse: an edit that changes chunk boundaries can still require several new vectors.
7. **Worklet:** the speech worklet declares `use_dynamic_url: true`. A fixed-ID webpage fetch is refused while actual player speech still works in isolated Chromium. This reduces fixed-address fingerprinting; it is not a promise of universal extension undetectability. See [Chrome's manifest documentation](https://developer.chrome.com/docs/extensions/reference/manifest/web-accessible-resources).
8. **Article selection:** capture considers up to 16 visible article/main containers and chooses the one with the most rendered text, retaining the 2,000-word/8,000-text-node extraction limits and excluding form/editor/hidden contents.

## Upgrade and storage

Database schema 5 prepares normalized text in existing web passages, legacy captions and OCR rows during a one-time upgrade. It does not download old pages or re-run embedding models. Vectors, original text, video times, watch dates and import flags are preserved. Additional normalized web text is included in the existing 64 MiB accounted full-content budget. If necessary the oldest full web content falls back to its retained title/query; this can happen during upgrade for a library already near the limit. Title vectors/metadata, database overhead, legacy video stores and model memory remain outside that web-content budget. Export first if you want a separate copy of all existing full text. Old backups still restore and rebuild derived normalized fields.

Reload the same installed folder and refresh open tabs. Website permissions and audio remain opt-in. No vendor rebuild or dependency change is needed for v2.13 and later.

## Verification and measurements

All **194 Node tests** pass, including the supplied public URL examples, unsafe redirect targets, Chrome/Activity deduplication, batched embedding/notification counts, duplicate imports, canceled batches, exact passage reuse, Unicode/quoted lexical rescue and word boundaries. Restoring the broad full-path filter deliberately makes its new regression fail; the correct filter was restored.

Isolated Chromium checks cover schema-4 → 5 migration of 100 web entries plus legacy captions/OCR, retention of all 101 titles and original dates, normalized text, timestamp preservation and budget enforcement. The migration fixture downgrades seven old full-content entries while keeping their titles. Real-model article search passes with a hidden login form and visible small comment box, picks the longer article, excludes form/editor contents, rejects a dominant editor and visible password field, and does not save a minor edit after 11.5 seconds. Controlled HTML video tests pass real native captions, CLIP scenes, OCR, English Whisper, time links and backup restoration with the dynamic worklet URL. Production Instagram/TikTok playback remains outside this controlled-test guarantee.

The reproducible `node tests/bench/search.mjs` comparison uses 30,000 synthetic full passages (183 words each) across 2,000 items against v3.0's ranker. On the test machine, ranking improved from **1,399 ms to 142 ms**, with identical returned IDs/timestamps. Cached normalization excludes one-time migration and the measurement excludes IndexedDB, model loading and query embedding; it is not an end-to-end or general accuracy guarantee.

The real IndexedDB/MiniLM browser test additionally searches **600 full 2,000-word synthetic pages**, 9,000 content passages and about **51.9 MB** of accounted full-content payload. Warm searches measured **107–161 ms**, including database scan/ranking and query embedding but excluding cold model load. The older 2,000-short-item check remains a separate fixture and measured 30–80 ms. A 100-long-transcript fixture stays below 64 MiB, preserving title-only entries after eviction. No user history is used. Existing YouTube scene/storage and automatic speech regressions are also checked.

The dependency graph is unchanged; the native audit still reports three high and one moderate findings previously documented in TEST-REPORT.md. Affected native Node dependency paths remain excluded from the browser bundle; the graph is not audit-clean.
