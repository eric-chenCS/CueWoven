# Recall v2.13 — on-screen words and more scene coverage

Recall now converts English text baked into a video's pixels into searchable words with the sampled video's timestamp. It shares the normal search with captions, audio, titles and scenes. Results show **On-screen text**, quote the recognized words and open near that time. No additional search mode is needed.

**Read on-screen text** is on by default and has its own off switch. After the watch delay it samples a temporary JPEG up to 1280 × 720 every five seconds of visible, normal playback. A local English Tesseract worker reads a lower-frame subtitle region and a sparse full frame, filters low-confidence fragments, and embeds the words with the existing MiniLM model. A single frame runs at a time; busy frames are skipped instead of queued. Repeated nearby text is deduplicated. Sharp frames are discarded, and the worker releases after 60 idle seconds. Navigation, pauses, seeks, ads and background history-capture tabs are excluded. Disabling capture cancels pending OCR saves. Recognized text has timestamp links, follows retention/deletion and survives caption replacement and backup restore. Limits are 720 text moments per video and 10,000 total. Backups restore text in batches of at most 16.

Scene capture keeps its 20-second interval and 320 × 180 image size. Limits increase from 120 to **240 per video**, and from 1,000 to **2,000 total**. A **24 MiB compressed-image/vector payload budget** also applies on scene writes, deleting oldest images first. This is a storage budget, not a cap on all extension RAM or IndexedDB's internal overhead. JPEGs now use binary Blobs rather than base64 strings in IndexedDB. Search loads vectors and metadata; only selected previews decode to data URLs. Existing JPEG bytes, timestamps and watch dates are preserved by the schema-3 migration; budget eviction occurs on subsequent scene writes. Duplicate-frame checks keep only a small SHA-256 fingerprint after OCR, releasing the temporary sharp image. More retained frames add about 2 MiB of vector payload at the maximum, without more frequent frame capture or CLIP inference.

## Validation

- All **145 Node tests** pass, including source/timing guards, pause/visibility/seek/ad checks, OCR confidence filtering, sharp-frame bounds, source indicators, cancellation/load races/deadlines/idle release and bounded backup batches. Removing the OCR ad guard deliberately failed its regression; the guard was restored.
- The real bundled OCR engine read both lines of a burned-in English subtitle fixture and a title near the top of another image. A blank image produced no text. One measured run took about 399 ms on first use and 72 ms for the next fixture, including both recognition passes. Initial sparse-only/compressed input tests misread the subtitle; lower-frame layout plus sharper temporary JPEGs resolved that fixture.
- Automatic canvas-to-video playback, actual OCR and actual MiniLM produced a timestamped **On-screen text** hit for a video with no caption or audio transcript. The real file-input backup restore preserved its words/timestamp, and deletion removed them. Caption replacement preserved the OCR count. Light/dark result screenshots were inspected; no horizontal overflow was found.
- The v2-to-v3 storage test preserved the exact JPEG and original watch date, exercised 2,000 scene vectors, and verified no image data appears in search metadata. Median ranking was about 0.7 ms for both 1,000 and 2,000 fixture rows; reading 2,000 metadata rows took about 40–42 ms. A deliberately noisy-image library was reduced to 859 rows / 25,142,071 accounted bytes, below 24 MiB. That deliberately large eviction took about 314 ms in the first run and 3.4 seconds in a later package run; large cleanups can take longer than ordinary captures. An ordinary write with 2,000 scene records measured about 137 ms in an additional run. OCR text caps and pruning counts also passed. These are isolated-machine fixture measurements, not a device-wide memory or sustained-playback benchmark.
- Existing default arrows/keyboard, refinement, automatic Whisper playback, both 53-video imports, six-player background queue, legacy embedding upgrade, import provenance/restore/title notices, and real CLIP unified scene/backup/retention regressions passed.
- A public-player attempt using the video from the user's screenshot could not start playback within its deadline in isolated Chromium. It did **not** verify live public-video OCR. Successful subtitle tests use controlled video pixels with real models, media playback, storage and extension code. No user cookies/history were read.

## Runtime and update

Version **2.13.0** adds pinned Tesseract.js 7.0.0 and English trained data 1.0.0. Code, the selected LSTM core and English OCR data load locally; no OCR API, upload or new browser permission is used. Scalar, SIMD and relaxed-SIMD LSTM variants add roughly 14.8 MB to the extracted runtime; only the compatible core loads. Third-party notices are under licenses/. MiniLM, Whisper and CLIP keep their existing first-use weight downloads. Native pnpm audit still reports the same 3 high sharp / 1 moderate sprintf-js advisories in existing Node paths, excluded from the browser runtime; no new OCR dependency advisory was reported. The source dependency graph remains not audit-clean.

For Git checkouts, run `pnpm run setup` after pulling because the runtime changed. Packaged copies already contain it. Keep the installed folder path unchanged, reload Recall and refresh YouTube tabs. Existing history and snapshots need no re-import. The shipped package excludes user data, browser profiles, node_modules and downloaded Hugging Face model caches; the licensed English OCR data is intentionally included.

Sampling can miss subtitles that appear between frames. English-only OCR may misread small, stylized, moving or low-contrast lettering and is not a full-video transcript. It saves a sample timestamp, not the exact subtitle onset/end. Existing snapshots and past imported videos are not retroactively OCR indexed. Protected players can block image reading. Both visual features use additional CPU/models; their off switches remain available. Minimum-browser compatibility, arbitrary-language recognition and sustained resource use on the user's regular Edge profile were not certified by these tests.
