# Review — Recall v2.10.0

Reviewed correctness, readability, module boundaries, security and resource use against the requested ma-copy adaptation and unified recall. Detailed branch findings and measured comparisons are in MA-COPY-REVIEW.md. The release retains current pagination, refinement, audio coverage and CLIP scenes; it does not replace main with the older teammate branch.

Transcript/audio vectors exclude repeated title text, while titles/channels contribute bounded lexical context. Exact speech and Unicode word handling have regression tests. Raw ranking values are no longer displayed as probabilities. Source text and progress errors render through textContent. No new permissions, inference service or dependency is introduced. Separate model spaces and existing validated scene/audio boundaries remain intact.

Old vectors upgrade in batches of 16 without rewriting videos or blocking the first search. Each write checks the current chunk and parent in a transaction; browser tests verify newer captions, dates and deletion win races. Revision-aware index reads prevent an invalidated in-flight build becoming the cache. Temporary mixed embedding recipes and first-use CPU work are documented. Existing caps, bounded media workers and sampled coverage remain unchanged.

All 113 Node checks pass; disabling phrase matching failed the new regression and was restored. The real-model upgrade, scene, speech, import, pagination and refinement browser tests pass. The background-window manual-close UI check timed out once, then passed alone with diagnostics; its original timing cause is unconfirmed. The extracted v2.10 package also passed the legacy-upgrade and background-window regressions; the manual-close path completed on that packaged run. Live public-video evidence and the narrow model comparisons are documented in TEST-REPORT.md. Existing native-only audit findings remain deferred outside the browser build, with no new dependency changes. No confirmed release-blocking defect remains in the tested scope; the intermittent browser-test timeout remains a validation limitation.

# Historical review — Recall v2.9.0

Reviewed scene capture, storage migration, multimodal ranking, rendering and resource limits against the request for one search with evidence indicators. No mode selector ships. Scene images originate in the isolated script's current video element, not desktop/tab screenshots. The background validates the normal watched-video source and capture settings; the image boundary restricts JPEG size/dimensions before decode. External image URLs and oversized/decompression-bomb headers are rejected. Only local image vectors/text queries reach CLIP; images remain in IndexedDB and validated backup files. The browser permissions and dependency lockfile are unchanged.

Scene storage shares the existing database, with transactional caps/counts and preserved scene metadata across transcript replacement. Delete/clear removes images, age pruning updates counts, and backups re-embed image vectors. Existing transcripts survive the v1-to-v2 schema upgrade in the browser regression. Candidate ranking uses separate model spaces, reciprocal ranks and explicit source labels; raw CLIP scores are not treated as MiniLM probabilities. Nearby evidence and tie preferences are documented heuristics. Search reads image data only for final selected results. A busy visual worker does not accept an unbounded frame backlog and keeps only the newest waiting query; idle workers are released.

All 101 Node tests passed; an inverted ad-exclusion mutation was detected and restored. The scene browser regression passed automatic playback frames, a visual query, a separate transcript query at 0:42, indicators/previews, migration, backup restore, caps, retention and deletion. Both visual/light and dark UI screenshots were inspected. The speech regression, both 53-video history imports, default arrow navigation, refinement and six-player background caption queue passed. One live public YouTube session saved both speech and a scene, and its unified search returned AI speech + Scene evidence around 0:11. The native dependency audit still reports 3 high and 1 moderate findings in the previously deferred native Node graph, outside the shipped browser build.

Known limits remain: sampled coverage, approximate image matching, English descriptions, possible unreadable/protected players, additional model downloads/CPU/memory and the oldest-image caps. No sustained device-performance or universal recognition guarantee is made. No unresolved release-blocking finding was identified in this tested scope.

# Historical review — Recall v2.8.0

Reviewed the automatic speech fallback across correctness, module boundaries, input validation, privacy, cleanup and resource use. Audio originates in the isolated content script's current player, is transferred as bounded PCM packets and is never persisted or uploaded. No microphone, tabCapture, activeTab or other new permission was added. Only trusted extension contexts can forward audio-open/close controls; the controller validates the session/tab before accepting packets. Captured history tabs are excluded. Text renders through textContent, and full captions take precedence transactionally.

Review fixes include end/navigation cleanup, canceled module-open protection, packet-error cleanup, session-aware failure handling, the settings off switch, tab closure and coalesced progress updates. The browser test now waits for actual media end and explicitly polls backend state before restarting. The new Node tests cover automatic/deferred fallback and excluded caption/history cases. Removing the pause/ad guard failed the speech regression and was restored. All 87 Node tests, the real-model speech browser test, the existing import/search/background regressions and one actual public YouTube speech fallback passed. The speech UI screenshot was inspected.

Known practical limits are documented: English recognition errors, approximate timestamps, partial played coverage, first-use downloads, extra CPU, one live session, bounded backlog and unsupported/protected players. The unchanged locked dependency audit still reports native Node findings; the affected paths are not in the shipped browser runtime. This review does not certify every YouTube video, minimum browser version or sustained hardware performance. No unresolved release-blocking finding was identified in the tested scope.

## Important qualification

The supplied caption-toggle suggestion was a reasonable hypothesis, not an established fix. The baseline also failed with captions already enabled. In v2, two headless live video attempts and a visible-browser repeat all failed, while caption state was restored correctly. Do not advertise live spoken-content capture as working based on the controlled tests.

The on-device title-search/import path is independent of live caption retrieval. Existing Recall backups containing transcripts still support spoken-content search.

The transcript-panel fallback now supports both legacy and newer view-model layouts. A final live repeat still failed. YouTube's native captions also failed without Recall in isolated Chromium and Edge profiles, so the remaining live failure is not specific to the extension. The normal signed-in Edge session needs a separate check.
